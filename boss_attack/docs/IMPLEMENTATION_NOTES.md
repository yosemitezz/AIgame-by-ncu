# 实现记录

## 谱面

每条约有效定时 note 换算：

```text
t = (beat[0] + beat[1] / beat[2]) * 60 / BPM + Offset / 1000
```

`time`、`effect`、audio note 的 `offset` 均不是逻辑来源。带 `sound` 的记录只计入原始 note 数，不进入定时、分组、激光或阶段计算。

分组键使用三个 beat 整数的精确字符串，例如 `73:0:4`。因此数值相同但分量不同的 beat 不会被合并。普通 note 组同时包含 column 1、2、3 时标记为重鼓，有无 column 0 不影响重鼓身份。

战斗阶段按所有起始 beat 与激光 endbeat 排序，间隔严格大于 4 拍时分割。新谱面重新计算得到 21 段。

每个阶段内，至少三个等间隔 timing group 的连续序列会拆成两 note 一组。拍间隔大于 1.01 拍时，一组作为普通动作句；一拍及更密时，相邻两组合成四 note 动作句。

同拍至少两个 laser note 会形成一个 `fixed_attack_event`。只有第一条记录负责触发固定招式1，避免同一正方体被重复生成。

## 时钟

桌面播放使用：

```text
playback_position + time_since_last_mix - output_latency
```

音乐和谱面均从同一 0 秒播放点开始。Headless 验证没有可靠音频输出时使用确定性手动时钟，以保证调度测试可重复。

## 重鼓

每个 timing group 只生成一个重鼓标记。判定延后到拍点后 125ms 才结算，以便接受晚格挡；一条输入可以在各自窗口内独立命中多个接近的重鼓。

左 Shift 目前只提供命中/失误视觉与音频反馈。用户尚未确认格挡成功后的生命、硬直或 Boss 状态效果，因此程序不擅自加入这些数值结果。

## 阶段和弹幕

阶段结束时停止新动作句，已有弹幕按自身 TTL 离场。重鼓与激光是独立事件，不会被单一 Boss 状态吞掉。普通 timing group 的 column 不绑定招式槽位。

## Boss 动作

- 招式1：2 拍瞄准锁定位置，2 拍冲撞，末尾 8 方向环形弹。
- 招式2：闪现左侧，横穿全场并分三次向上下撒弹。
- 招式3：先三路扇形弹，再沿中央方向冲撞。
- 招式4：冲向锁定位置后释放两圈错位弹幕。
- 加速段依次循环“冲弹弹弹”“弹弹冲弹”“双冲”“四连弹”。
- 固定招式1：正方体飞行 2 拍、预警 2 拍，然后产生两条全屏对角线激光。

除固定招式1外，所有冲撞目标都在动作句起点锁定，之后不追踪玩家。

## 范围边界

训练弹幕已关闭。Boss 模型与招式贴图保持空槽，程序几何仅用于逻辑、碰撞和可躲空间验证。
